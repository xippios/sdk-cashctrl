# Upstream documentation snapshot — CashCtrl

Source of truth for every endpoint wrapper (sdk-core ADR-0028). The files in this
directory are written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the
pages in the table below and refreshed deliberately by PR, so that changes show up as
diffs. This file is generated by the same script; nothing here is edited by hand but
`OBSERVED.md`, where it exists: what upstream does but never documents, each note with
its evidence.

  logo in the page's footer
- `Terms of Service`, a link to https://cashctrl.com/en/about/terms, printed at
  https://app.cashctrl.com/static/help/en/api/index.html: the error handling's link to
  CashCtrl's terms, on delays between requests

The script stops when a page it reads states one it does not record, or no longer prints
one it records. The documentation's text is reproduced here as this package's reference
(sdk-core ADR-0028); the publisher's objection is met by replacing it with a summary
that keeps the names and semantics the wrappers rely on.

## How this is captured

The documentation is one server-rendered HTML page whose table of contents links to its
sections by fragment (`#intro`, `#/account`). The script fetches the page once and
writes one Markdown file per top-level entry of the table of contents, named after the
entry: the five general sections, then one file per module holding all of the module's
controllers. Each file starts with one line, the URL of its entry; the fetch time is
recorded only in this file. Headings keep the page's levels: `##` controller, `###`
operation, `####` Parameters, Endpoint or Example; each paragraph is one line.

Navigation (table of contents, breadcrumbs, anchors), scripts, styles, the footer and
the parameter names the page repeats for small screens are dropped; the arrow icons
between menu items become →. `toc.js` (scrolling and table-of-contents highlighting) and
`main.css` are not captured. Endpoints, curl examples and JSON responses become fenced
code blocks, verbatim. Every table on the page is a two-column parameter table; it
becomes a pipe table with an empty header row and three columns: name, labels (mandatory
or optional, data type, limits) and description. A table for which the page gives no
labels has two columns, name and description. A table that nests another (the fields of
a JSON parameter) cannot be a pipe table and stays an HTML table with the same columns,
reduced to code, links and line breaks. Links into the page are absolute. The script
stops unless every section shows the same words, in the same order, on the page and in
the Markdown.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched: a converted page's row
holds the HTML page's, an excerpt's the whole document's, a file split from a page the
page's. Last-Modified is the HTTP header in UTC, or as sent in a code span where it is
no HTTP date, and ETag is as sent, in a code span, on a row that ends in a comment
telling the secret scan it is no key. A page recorded without a file is `(no file)`, and
a body that changes on every request records no size, sha256 or ETag. A sample is a
small answer of the API kept verbatim under `samples/`, which documents the answer's
shape and is no test fixture. Requests go one at a time, 2 s apart, through core's
client, each retried at most once and no sooner than 10 s, a 429 after the wait the
client gives it where that is longer, and are identified as `xippios-cashctrl/<version>
(+https://github.com/xippios)`, the source package's version in place of `<version>`. No
redirect to another host is followed and no browser is imitated. No key is sent or read.
A page an anonymous client cannot read is requested once and listed under Not fetched.

## Vendor examples

The page's examples contain the vendor's placeholder API key and example pre-authenticated
object-storage URLs; they are reproduced verbatim from the public page and are not
credentials of this project.
